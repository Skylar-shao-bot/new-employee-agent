# AccessFlow — Agent 行为规则表

| 场景 | 判断条件 | Agent 行为 | 是否打断经理 | 前端反馈 | 边界 / 禁止 |
|---|---|---|---|---|---|
| 自动 | 用户意图明确；HR/岗位模板/项目/权限规则可补齐必要信息 | 自动检索、核对、补齐并继续 | 否 | 已核对 / 已匹配 / 已读取 | 不能把推断当作已核验事实 |
| 询问 | 存在关键缺失或冲突；且无法从已有系统解决；会影响方案 | 只询问最少必要问题，获得答案后重新核对 | 是 | 1 项信息需要确认 | 不要为了字段完整而反复追问 |
| 等待确认 | Agent 已生成方案，但经理尚未确认 | 停止创建/执行动作，等待经理授权 | 是 | 待经理确认 | 经理未确认前不得创建任何账号或权限 |
| 等待审批 | 权限项触发数据/生产/管理类审批规则 | 提交/记录审批状态并等待对应负责人 | 通常否 | 等待数据负责人审批 | 经理确认 ≠ 审批通过 |
| 停止 | 关键身份无法确认、规则冲突无法形成安全方案、明确禁止的权限请求 | 停止推进该项或整单，解释原因 | 是 | 无法继续 / 规则冲突 | 不能绕过硬规则或自行放宽权限 |
| 转人工 | 自动化无法安全恢复，例如许可证不足或需要人工处理 | 记录原因、保留已完成项、交给对应人工角色 | 视情况 | 需要人工处理 | 成功项不得重复执行 |
| 查询而非重试 | 系统超时且没有最终结果 | 查询原请求状态 | 否 | 结果未知 / 查询结果 | UNKNOWN 不得直接重试 |
| 完成 | 权限项已有明确成功结果 | 记录申请编号、时间、结果并锁定为成功 | 否 | 成功 | 禁止重复开通 |
