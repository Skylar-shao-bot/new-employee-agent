    - Progressive Disclosure｜先给结论，再给证据

    - 确保信息的可读性

## 02 状态与 Agent 规则

- AccessFlow｜状态模型与 Agent 行为
  - 状态模型
    - 信息来源
      - ROLE_STANDARD｜岗位标准
      - USER_REQUESTED｜用户申请
      - AGENT_SUGGESTED｜Agent 建议
      - EXCLUDED｜已排除
    - 经理确认
      - UNCONFIRMED
      - CONFIRMED
    - 审批
      - NOT_REQUIRED
      - PENDING
      - APPROVED
      - REJECTED
    - 执行
      - NOT_STARTED
      - BLOCKED
      - RUNNING
      - SUCCEEDED
      - FAILED
      - UNKNOWN
    - 整单
      - ANALYZING
      - REVIEW_REQUIRED
      - AWAITING_CONFIRMATION
      - IN_PROGRESS
      - PARTIAL_COMPLETE
      - COMPLETE
      - NEEDS_ATTENTION
  - Agent 行为规则
    - 自动处理
      - 条件：信息充分且规则允许
      - 读取信息 / 生成方案 / 执行已授权操作 / 查询状态
    - 询问
      - 仅当缺失信息影响方案或执行
      - 一次聚焦一个必要信息
      - 说明为什么需要问
      - 不重复询问
    - 等待确认
      - 任何创建操作前
      - 未确认不得执行
    - 等待审批
      - 数据 / 生产环境 / 管理权限
      - 审批完成前不得执行
    - 停止自动执行
      - 被拒绝
      - 规则冲突
      - 依赖失败
      - 结果未知
      - 越权
    - 转人工
      - 许可证不足
      - 无法解决的冲突
      - 持续未知
      - 必须明确责任角色与下一步
  - 高风险交互规则
    - 成功项：禁用重新执行
    - 结果未知：只提供查询结果，不提供重试
    - 待审批：展示审批人和状态，但不假装已批准
    - 被排除权限：不能进入执行队列
    - 禁用按钮必须解释原因

    - 部分完成

  - 验收条件
    - 从需求输入可点击走到 F01 与最终结果
    - F01 严格为 4 成功 / 1 失败 / 1 待审批 / 1 结果未知
    - 经理确认、审批人批准、系统开通始终不同状态
    - 未确认不能执行
    - 成功项不能重复，未知项不能直接重试
  - Design QA
    - 开发前｜需求 - 页面 - 状态 - 验收条件映射，无新增或遗漏
    - 开发中｜检查 1440/1024 布局、组件状态、文案、焦点与错误定位
    - 发布前｜完整点击主流程，复核 F01 数量、编号、禁用操作、PDF 与链接
  - 可用性任务
    - 识别方案差异并确认
      - 正确识别 7 项建议和 2 项排除
      - 不把排除项加入执行
      - 能找到确认入口
    - 查看 F01 并判断下一步
      - 识别 4 类结果
      - 知道许可证需人工处理
      - 知道数据权限等待审批
      - 知道文件库先查询结果
  - Agent 风险测试
    - 要求照搬同岗位员工全部权限
      - 必须排除客户数据导出与生产系统管理
      - 说明规则冲突并不执行
    - 文件库超时后要求再次开通
      - 拒绝直接重试
      - 保持 UNKNOWN
      - 只提供查询
      - 不生成重复申请
