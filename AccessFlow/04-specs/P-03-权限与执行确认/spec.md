## 0. 和审阅页怎么分工

P-02 回答「**开什么、为什么排除**」。P-03 回答「**确认之后谁来做、会怎样**」。

| | P-02 开通方案审阅 | P-03 权限与执行确认 |
|---|---|---|
| 用户任务 | 改范围 / 有效期 | 勾选将执行的项，核对执行结果，授权开始处理 |
| 主问题 | 建议开通 7 项，排除 2 项 | 6 项 Agent 执行，1 项送审 |
| 列表里有什么 | 7 项建议 **+** 2 项排除 | **7 项建议 + 勾选（默认全选）**；排除项不出现 |
| 排除项 | 独立「不应开通」表，必须看见 | **不出现**。上一页已经审过 |
| 已取消勾选 | 本页没有勾选 | 行留在原执行组，文案「确认后不会开通此项」 |
| 分组轴 | 可直接执行 / 需要审批 | **执行主体**（Agent / 人工执行 / 送审） |
| 可否编辑范围 | 可以 | 不可以；要改就回 P-02 |
| 可否勾选开通 | 不可以 | **可以，默认全选** |
| 主按钮 | 继续确认执行 | 确认方案并开始处理 |
| 本页会不会开通 | 不会 | 点主按钮后才开始；本页本身仍未开通 |

陈晨默认路径（7 项全勾选）：

```text
P-02 看见：建议 7 + 排除 2
                ↓ 继续确认执行
P-03 看见：将处理 7 = Agent 执行 6 + 送审 1
           排除 2 项不进本页
```

「1 项送审」必须单独成组、先于细节被看见，不能混在 6 项自动执行里。

## 1. 页面目标与 P-02 衔接

用人经理在审阅页点「继续确认执行」进入本页，核对确认后的执行分工，再授权开始处理。

| 项 | 内容 |
|---|---|
| 路由 | `/confirm`（P-02 主按钮 `navigate('/confirm')`） |
| PRD 页面 | P-03 权限与执行确认 |
| 导航布局 | **同一 SideLayout**。当前菜单仍是「新建开通」（尚未 CONFIRMED，未进入执行） |
| 主用户（壳层） | 与首页 / P-02 一致：界面「李经理」 |
| 员工事实 | 陈晨；直属经理字段为王璐 |
| 进入 | P-02 状态 `navigating`：主按钮 loading 后进入；**不再**打 Toast（P-02 也没有进确认 Toast） |
| 成功出口 | 「确认方案并开始处理」→ 写 CONFIRMED → P-04 `/progress` |
| 返回出口 | 「返回修改方案」/ Steps 第 2 步 → P-02 `/plan`，**保留会话方案** |
| 回首页 | Steps 第 1 步 / 侧栏「新建开通」→ P-01 `/`，方案仍在 sessionStorage |
| 面包屑 | **不展示** |

本页**不创建账号、不代替审批人批准、不把排除项加回队列**。点主按钮 = 记录经理确认：允许的项开始执行，送审项进入待审批。

### 1.1 从审阅页带过来的事实

| P-02 产出 | 本页怎么用 |
|---|---|
| `sessionStorage` 方案（勾选、范围、有效期、经理已修改） | `loadStoredPlan()`；列表只渲染 `selectedKeys` 对应行 |
| 员工摘要 | 同一张卡、同一套字段，只读 |
| 7 项建议 / 2 项排除 | 建议项按勾选过滤；排除项 **整组不渲染** |
| 指标 7 / 6 / 1 / 2 | 改成执行口径：将处理 / Agent 执行 / 送审（默认 7 / 6 / 1） |
| 「继续确认执行」 | 本页主按钮换成确认文案，不再出现「继续确认」 |
| 编辑抽屉未保存 | 进不了本页；P-02 会先拦 |

直达 `/confirm`（静态演示、跳过审阅）时，按默认全选 7 项展示，当作「方案已审阅且 7 项均勾选」。不要因为没有 session 就空白，也不要因此把 2 项排除画出来。

### 1.2 硬规则

- 确认 ≠ 审批 ≠ 开通：主按钮、说明条、送审组标题必须同时把三件事说清
- 排除项永不进执行队列，也**不在本页占一行**
- 本页可勾选是否开通，默认全选；要改范围 / 有效期，必须回 P-02
- 状态必须有文字，不能只靠颜色
- 确认成功后不可再改方案、不可回到可编辑的 P-03

### 4.1 信息层级

1. 壳：还在「新建开通」  
2. Steps：整单走到第 3 阶段（确认）  
3. PageHeader：当前任务是确认执行结果，不是再审一遍方案  
4. 指标卡：将处理 7 / Agent 6 / 送审 1  
5. 执行分组：按主体，空组不出现  
6. 底部：回上一页或真正确认  

### 4.2 流程 Steps

与 P-02 共用 `stageSteps()`。本页 `current={2}`。

| index | title | 对应 | 本页状态 | 点击 |
|---|---|---|---|---|
| 0 | 新建开通 | P-01 `/` | `finish` | 回首页，保留会话方案 |
| 1 | 开通方案审阅 | P-02 `/plan` | `finish` | 回审阅，可继续改 |
| 2 | 权限与执行确认 | P-03 `/confirm` | `process` | 已在本页则滚到顶部 |
| 3 | 执行进度 | P-04 `/progress` | `wait` | 不可跳步 |

第 0、1 步可点，体现「确认前还能回去」。第 3 步 `disabled`。确认成功进入 P-04 之后，禁止再回到可确认的本页。

当前步同时用 `process`、字重、主色。`aria-current="step"`。

## 6. 本页组件规格

壳层控件见首页 §6。员工卡、指标卡视觉拷 P-02。

### 6.1 页面说明提示条

本页核心误解是「确认 = 已批准 / 已开通」，以及「排除项是不是还要再看一遍」。用 info 条一次说清。

| 项 | 规格 |
|---|---|
| 组件 | `Alert type="info"` `showIcon` `closable` `className="ds-page-inline-alert"` |
| 只使用 | `message` 单行；禁止 `description` |
| 默认（7 项全选） | 上一页已审阅 7 项建议、排除 2 项。本页只列出将进入处理队列的 7 项：6 项由 Agent 执行，1 项送数据负责人审批。确认 ≠ 审批，未确认前不会开通。 |
| 勾选不足 7 | 数字跟当前勾选走，例如「本页只列出将进入处理队列的 6 项」 |
| 有依赖断裂 | 追加一句：有 n 项依赖已取消的公司账号，确认后无法执行。 |
| 关闭后 | 副标题末尾 `Button type="link"`「查看说明」 |

高度约 38px；文案过长时允许自动换行，不要改成 `description` 双行结构。

### 6.2 员工摘要

**与 P-02 §6.2 完全相同**，只读。不要缩成一行 chips，不要在本页改字段。这是「接到上一页」的锚点：经理扫一眼就知道还是陈晨这张单。

### 6.3 同级指标卡

3 张独立 `StatisticCard`，`className="ds-statistic-card"`，`bordered={false}`，**直接落画布**。禁止 `StatisticCard.Group`。默认两列；出现「需人工执行」项时才变成 3 张。

```text
grid-template-columns: repeat(2, minmax(0, 1fr)); /* 有人工执行组时 repeat(3) */
gap: var(--margin-sm);
```

| 指标 | value（默认） | suffix | icon | 色 | description |
|---|---|---|---|---|---|
| Agent 将执行 | 6 | 项 | `RobotOutlined` | success | 确认后进入开通队列 |
| 将送交审批 | 1 | 项 | `AuditOutlined` | warning | 数据负责人；批准前不开通 |
| 需人工执行 | 仅 count>0 时出现 | 项 | `UserSwitchOutlined` | default / purple 辅助 | 确认后交给对应人工角色 |

陈晨主路径没有「确认前已知必须人工执行」的项，**第三张卡默认不出现**。设计工具仍算 Agent 执行，条件写在行内（见 §6.4）。

不要「将进入处理」汇总卡，也不要「不应开通」。排除计数属于 P-02；总数由下方分组标题承担。

### 6.4 执行分组（本页主模块）

按 **执行主体** 分卡，不按来源分卡。来源单独成列（与 P-02 同一套 SourceBadge），方便对照上一页，但不再承担分组。

空组 **整卡不渲染**，不要 Empty 插画。

#### 组 A · Agent 将为你执行

| 项 | 规格 |
|---|---|
| 标题 | `Agent 将为你执行（n 项）` |
| 组说明 | 确认后立即进入开通队列。依赖公司账号的项会等账号成功后再执行。 |
| 默认成员 | 公司账号、邮件与即时通信、知识库、Atlas 项目看板、设计工具、Atlas 项目文件库 |
| 卡片 | `ds-page-card ds-table-card-padded` |
| 表格 | 有勾选、无分页；右侧固定「编辑」列，点进 P-02 打开对应项编辑抽屉 |

设计工具留在本组：确认时许可证是否足够还未知。行内条件 Tag「需可用许可证」，确认后文案写清「Agent 先检查许可证；不足则转工具管理员」。不要在本页预标失败。

#### 组 B · 需人工执行

确认时已经知道 Agent 无法自动开通、必须交给人工角色的项。陈晨默认 **0 项，整卡不出现**。

| 项 | 规格 |
|---|---|
| 标题 | `需人工执行（n 项）` |
| 组说明 | Agent 不能自动开通这些项。确认后交给对应人工角色，本页不会替你执行。 |
| 何时出现 | 例如后续若在 P-02 就把许可证判为不足；本期演示不出现 |
| 与 F01 的关系 | F01 的「设计工具失败 → 转人工」发生在 **执行之后**，不提前搬到本组 |

本期必须把这个组写进信息架构，避免下一页才发明第三种主体。

#### 组 C · 将送交人工审批

| 项 | 规格 |
|---|---|
| 标题 | `将送交人工审批（n 项）` |
| 组说明 | 经理确认不是批准。这些项会进入待审批，批准前不会开通。 |
| 默认成员 | 产品数据看板（审批人：数据负责人） |
| 必须看见 | 审批人角色、批准前不开通 |

若经理在本页取消了产品数据看板，本组 count=0，整卡仍保留（方便再勾回）；指标「将送交审批」为 0。

### 6.5 行字段（只读）

列比 P-02 少，换成「确认后会发生什么」。无编辑抽屉。**有勾选列**，默认全选。取消勾选后行留在本组，不进排除、不从本页消失。

| 列 | 宽 | 内容 |
|---|---|---|
| 勾选 | 48 | 是否进入处理队列；默认勾选 |
| 项目 | 168 | 图标 + 名称；未勾选行 `p02-muted` |
| 来源 | 140 | 与 P-02 同一套 SourceBadge，单独成列 |
| 权限范围 | 260 | 含「经理已修改」Tag（若 P-02 改过） |
| 有效期 | 120 | 长期 / 至 12 月 31 日 |
| 执行条件 | 168 | 依赖、许可证、审批；断裂时 warning Tag |
| 确认后将 | 240 | 见下表，这是本页主阅读列 |

陈晨默认「确认后将」：

| 项目 | 执行条件 | 确认后将 |
|---|---|---|
| 公司账号 | 条件已满足 | Agent 立即创建标准员工账号 |
| 邮件与即时通信 | 需先创建公司账号 | 等账号成功后，由 Agent 开通普通成员 |
| 知识库 | 需先创建公司账号 | 等账号成功后，由 Agent 开通全员只读 |
| Atlas 项目看板 | 条件已满足 | Agent 按项目成员开通，不可管理项目 |
| 设计工具 | 需可用许可证 | Agent 先检查许可证再开通；不足则转工具管理员 |
| 产品数据看板 | 数据负责人审批 | 提交给数据负责人；批准前不会开通 |
| Atlas 项目文件库 | 条件已满足 | Agent 开通项目目录读写，不含客户原始资料 |

公司账号被取消但依赖项仍勾选：执行条件改 warning「依赖公司账号，取消后无法执行」；确认后将改成「确认后无法执行，不会创建该项」。这些行仍留在 Agent 组（它们仍是「本想交给 Agent」的项），用文字说清结果，不要偷偷藏掉。

来源列跟 P-02：岗位标准蓝色文本；用户申请 orange Tag；Agent 建议 purple Tag + Robot；项目需要 success Tag。

### 6.6 不要出现的模块

- 「不应开通的权限」表  
- 编辑抽屉、批量操作  
- 把 7 项摊成一张未分组总表  
- 工单号、错误码、模型名（确认前还没有申请单号；P-04 才出现 REQ-…）  
- 主按钮写成「开始执行 / 已批准 / 立即开通」

### 6.7 底部操作栏

视觉拷 P-02 `.p02-footer`：吸底，白底，顶部分割，高 56px，按钮右对齐。

| 按钮 | 类型 | 文案 | 行为 |
|---|---|---|---|
| 次 | default | 返回修改方案 | `/plan`，不写确认 |
| 主 | `type="primary"` | 确认方案并开始处理 | 写 CONFIRMED，进 `/progress` |

主按钮规则：

- 0 项将处理：禁用 + Tooltip「请至少勾选一项将执行的权限」  
- 提交中：loading，随后禁用，防重复点击  
- 成功：`message.success('已记录确认。可直接执行的项目已开始处理，需审批的项目已进入待审批')` 后跳转  
- 失败（静态期不演示）：`message.error('确认未完成，尚未开始开通')`，留在本页，内容不丢  

页头 extra 的「返回修改方案」与次按钮同一路由，不要一个回首页、一个回审阅。

## 8. 交互与状态

### 8.1 主路径（接 P-02）

```text
P-02 review → 继续确认执行
  → /confirm（本页，UNCONFIRMED）
  → 阅读员工、3 个指标、Agent 6 项、送审 1 项
  → 确认方案并开始处理
  → CONFIRMED → /progress
```

返回修改：

```text
本页 → 返回修改方案 / Steps「开通方案审阅」
  → /plan（仍是未确认方案，勾选与修改都在）
  → 可再进本页；列表随勾选变化
```

陈晨主路径：不自动打开任何抽屉 / Modal。确认按钮直接提交。

### 8.2 本页状态机

| 状态 | 进入 | 界面 | 退出 |
|---|---|---|---|
| `unconfirmed` | 从 P-02 进入，或直达 `/confirm` | Steps 第 3 步；按勾选分组 | 确认 / 返回审阅 / 回首页 |
| `submitting` | 点主按钮 | 主按钮 loading 且随后禁用 | 成功 → P-04；失败 → 回 `unconfirmed` |
| `confirmed` | 写入成功 | 立即离开本页 | 不可停留、不可改方案 |

本页不出现：输入框、核对五步、排除表、编辑抽屉、开通回执、整页 Spin。

### 8.3 列表如何随 P-02 变化

| P-02 动作 | 本页结果 |
|---|---|
| 默认 7 勾选 | Agent 6 + 送审 1 |
| 取消「知识库」 | Agent 5 + 送审 1；知识库消失 |
| 取消「产品数据看板」 | 只剩 Agent 6；送审卡不渲染 |
| 取消「公司账号」，依赖项仍勾选 | 依赖行留在 Agent 组，条件 warning |
| 取消全部 | P-02 主按钮已禁用；若直达则本页主按钮禁用 |
| 修改范围并保存 | 本页显示新范围 +「经理已修改」 |
| 排除 2 项 | 任何勾选组合下都不出现 |

### 8.4 确认之后

- 写 `CONFIRMED`（静态：`sessionStorage`）  
- 进入 P-04；侧栏改为「正在执行」  
- 浏览器后退回到 `/confirm`：检测到已确认则 **重定向 `/progress`**，不要把已确认方案再拿来改  
- 不得把排除项写入执行队列（前端不展示；若误传，后端拒绝——静态期只保证不展示）
