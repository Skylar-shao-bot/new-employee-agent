## 1. 页面目标与首页衔接

用人经理在首页点「生成权限开通方案」，Agent 核对完成后进入本页，审阅 7 项建议和 2 项排除，必要时改范围 / 有效期，再进入确认。是否开通的勾选放在下一页。

| 项 | 内容 |
|---|---|
| 路由 | `/plan`（首页成功后 `navigate('/plan')`） |
| PRD 页面 | P-02 开通方案审阅 |
| 导航布局 | **同一 SideLayout**。当前菜单仍是「新建开通」（方案尚未确认，未进入执行） |
| 主用户（壳层） | 与首页一致：界面「李经理」 |
| 员工事实 | 陈晨；直属经理字段为王璐（PRD 冻结，不是壳层用户名） |
| 进入 | 首页状态 `navigating`：`message.success('已生成开通方案')` 后进入 |
| 成功出口 | 「继续确认执行」→ P-03 `/confirm` |
| 返回出口 | 「返回」/ Steps 第 1 步 / 侧栏「新建开通」→ P-01 `/`，**保留会话方案与原文** |
| 面包屑 | **不展示**。与首页相同，`breadcrumbRender={false}` |

本页**不创建账号、不执行开通、不代表经理已确认**。首页已经完成核对，本页**不再重放**五条核对 Steps。

### 1.1 从首页带过来的事实

| 首页产出 | 本页怎么用 |
|---|---|
| `rawRequest`（sessionStorage） | 返回 P-01 时原文还在；本页不展示输入框 |
| 核对五步已跑完 | 只展示结论，不重播「正在核对陈晨的人事信息…」 |
| `message.success('已生成开通方案')` | 进页后不再重复这条 Toast；改用页面说明条 |
| 陈晨演示数据 | 员工卡 / 7 项 / 2 项排除与 PRD 冻结表一致 |
| 继续处理任务卡 | **本页内容区不渲染**。恢复入口仍在侧栏「正在执行 / 开通记录」 |

直达 `/plan`（静态演示、跳过首页）时，仍展示完整方案，当作「方案已生成」。不要因为没有 session 就空白。

### 1.2 硬规则（PRD）

- 最小权限：不能把同岗位历史特殊权限加进执行队列
- 先确认后执行：本页只审阅
- 排除项不能看起来像待执行
- 状态必须有文字，不能只靠颜色

## 4. 主内容区结构

导航层不渲染业务标题。本页自己输出 `.ds-page-header`。禁止原生 `<h1>`。

```tsx
<div className="ds-page-shell">
  <Steps size="small" current={1} items={STAGE_STEPS} />

  <div className="ds-page-header">
    <Space direction="vertical" size={4}>
      <Title level={4} className="ds-page-title">开通方案审阅</Title>
      <Text type="secondary">
        审阅 Agent 刚生成的方案。确认后才会开始开通，现在不会创建账号。
      </Text>
    </Space>
  </div>

  <Alert type="info" showIcon closable className="ds-page-inline-alert" message={...} />

  <Card bordered={false} className="ds-page-card">{/* 员工摘要 */}</Card>

  {/* 同级指标卡 Grid，直接落画布 */}

  <Card bordered={false} className="ds-page-card ds-table-card-padded">{/* 可直接执行 */}</Card>
  <Card bordered={false} className="ds-page-card ds-table-card-padded">{/* 需要审批；空则不渲染 */}</Card>
  <Card bordered={false} className="ds-page-card ds-table-card-padded">{/* 不应开通 */}</Card>
</div>
{/* 吸底操作栏：返回 + 继续确认执行 */}
```

PageHeader **禁止** `padding-inline` / `padding-bottom`。与卡片间距只由 `.ds-page-shell` 的 `gap: var(--nav-space-4)` 承担。

标题规格与首页相同：`Title level={4}` 20px / 28px，副文案 `Text type="secondary"` 14px / 22px。不采用稿面营销大标题。

### 4.1 信息层级

1. 壳：还在「新建开通」  
2. Steps：整单走到第 2 阶段  
3. PageHeader：当前任务是审阅  
4. 指标卡：7 / 6 / 1 / 2  
5. 可直接执行 / 需要审批：可操作，分卡  
6. 不应开通：只读  
7. 底部：返回首页或去确认  

### 4.2 流程 Steps（本页新增）

首页没有 Stepper。从本页起，主路径内页用内容区 `Steps`，全站 **四步**；第四步标题随阶段切换（执行中「执行进度」→ 收口「执行结果」）。

`current={1}`，横向、`size="small"`、`titlePlacement="horizontal"`、`variant="filled"`。这是导览，**不是** `StepsForm`，也不是首页 PromptCard 里那条垂直核对步骤。用 antd 原生连接线：已完成段主色，未开始段禁用色。标题在圆点右侧，不要竖排标题，也不要手写 rail。

| index | title | 对应 | 本页状态 | 点击 |
|---|---|---|---|---|
| 0 | 新建开通 | P-01 `/` | `finish` | 等价「返回」 |
| 1 | 开通方案审阅 | P-02 `/plan` | `process` | 已在本页则滚到顶部 |
| 2 | 权限与执行确认 | P-03 `/confirm` | `wait` | 不可跳步 |
| 3 | 执行进度 | P-04 `/progress` | `wait` | 不可跳步 |

第 0 步标题用首页菜单名「新建开通」。P-04 / P-05 共用第 3 步索引，仅标题随状态变化。

当前步同时用 `process`、字重、主色。`aria-current="step"`。

### 6.4 建议开通分组（可直接执行 / 需要审批）

按执行状态拆成 **两张** `ds-page-card ds-table-card-padded`，不要合成一张「本次开通明细」。空组整卡不渲染（与 P-03 空组惯例一致）。排除项仍在独立「不应开通」卡，不进本组。

| 卡 | 标题 | 成员（默认） |

| 可直接执行 | `可直接执行（N 项）` | `execGroup === '可直接执行'`（默认 6 项） |

生成失败不得进入本页，因此本组没有 Empty。

列：项目、来源、权限范围、有效期、状态、备注、审批人、操作「编辑」。表体单行，`ellipsis` + Tooltip。操作列 `Button type="link"`，宽 80px，无图标。列溢出：`tableLayout="fixed"` + `scroll.x`，操作列 `fixed: 'right'`。

`centered`，480px。首页规定：普通业务弹窗 `centered`，操作类三段式。

文案：方案尚未确认。要放弃未保存的修改吗？　`放弃修改` / `继续编辑`。

仅抽屉有未保存改动时出现。本页没有勾选，不把确认页的勾选当成未保存。

吸底，白底，顶部分割 `1px solid var(--color-border-secondary)`，高 56px，左右 24px，按钮右对齐。层级低于 Drawer / Modal。

## 8. 交互与状态

### 8.1 主路径（接首页）

```text
P-01 idle → 生成权限开通方案 → analyzing（卡内五步核对）
  → message.success('已生成开通方案')
  → /plan（本页）
  → 阅读员工、4 个指标、7 项建议、2 项排除
  → 继续确认执行
  → /confirm
```

陈晨主路径：首页不询问，本页不自动打开抽屉。

### 8.2 本页状态机

| 状态 | 进入 | 界面 | 退出 |
|---|---|---|---|
| `review` | 从首页生成成功，或直达 `/plan` | Steps 第 2 步；7 建议 + 2 排除 | 编辑 / 去确认 / 返回 |
| `revalidating` | 抽屉保存 | 该行 loading，主按钮禁用 | 回到 `review` |
| `conflict` | 越权或照搬排除项 | 行内错误文案 | 改回合法值 |
| `leaving` | 返回且抽屉未保存 | Modal | 放弃 → P-01；继续 → 留本页 |
| `navigating` | 点继续确认执行 | 主按钮 loading | `/confirm` |

本页不出现：输入框、核对五步、继续处理任务卡、开通回执、整页 Spin。

### 8.3 返回首页

返回 / Steps[0] / 侧栏「新建开通」/ 浏览器后退：同一条路径 → `/`。

- 无未保存抽屉：直接走；首页 `sessionStorage` 原文仍在  
- 有未保存抽屉：先 §6.7  
- 范围 / 有效期修改保留在会话方案里，再进本页仍能看见  

有未保存抽屉时 `beforeunload`（与首页 analyzing 中关页相同机制）。

首页规定：有内容未提交点其他菜单，低风险直接走。本页例外：点「新建开通」等于返回，要走未保存确认；点「正在执行 / 开通记录 / 设置」仍按首页，低风险直接走（抽屉未保存则先确认，避免丢编辑）。

### 8.4 修改

抽屉保存并校验。是否开通在 P-03 勾选，本页不改指标卡。
